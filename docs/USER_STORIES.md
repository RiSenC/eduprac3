# Пользовательские истории

Проект: «Личный кабинет успеваемости студента» (Android, Kotlin + Room).
Роль: Product Owner. Истории сформулированы по разделу 4 ТЗ и уточняются по спринтам.

Статусы: **готово** — реализовано и проверено; **данные** — слой данных готов,
интерфейс появится позже; **в работе** — текущий спринт; **план** — будущие спринты.

## US-01. Общая сводка успеваемости (главный экран)

Как студент, я хочу сразу при открытии приложения видеть общий средний балл
и количество внесённых оценок, чтобы понимать свою успеваемость без перехода
по экранам.

**Критерии приёмки**
- [ ] На главном экране отображается средний балл по всем оценкам (одна цифра, 2 знака после запятой).
- [ ] Отображается общее количество оценок.
- [ ] Есть краткая сводка по дисциплинам (название и средний балл).
- [ ] Явно указано, что это среднее арифметическое по записям (веса не учитываются).
- [ ] Если оценок нет, показывается понятное сообщение, а не `0.00` и не `NaN`.

Статус: **данные** (`GradeDao.overallAverage`, `averageForDiscipline`), экран — спринт 3–4.

## US-02. Список дисциплин

Как студент, я хочу видеть список своих дисциплин с преподавателем и средним
баллом, чтобы выбрать предмет для работы.

**Критерии приёмки**
- [ ] Список строится по алфавиту.
- [ ] У дисциплины видны название, преподаватель (если указан) и средний балл.
- [ ] Дисциплины с одинаковым названием не создаются.
- [ ] При отсутствии дисциплин показывается пустое состояние с подсказкой.

Статус: **данные** (`DisciplineDao.observeAll`, уникальный индекс `name`), экран — спринт 3.

## US-03. Журнал оценок по дисциплине

Как студент, я хочу открыть дисциплину и увидеть все её оценки с датой, видом
работы и комментарием, чтобы вспомнить, за что получена оценка.

**Критерии приёмки**
- [ ] Оценки отсортированы по дате (новые сверху).
- [ ] Для каждой оценки видны значение, дата (дд.мм.гггг), вид работы и комментарий (если есть).
- [ ] Показан средний балл по дисциплине.
- [ ] При отсутствии оценок — пустое состояние, а не пустой список без объяснений.

Статус: **данные** (`GradeDao.getByDiscipline`, `DisciplineDao.getWithGrades`), экран — спринт 3.

## US-04. Добавление оценки

Как студент, я хочу добавить оценку с дисциплиной, значением, датой, видом работы
и комментарием, чтобы журнал был полным.

**Критерии приёмки**
- [ ] Обязательные поля: дисциплина, оценка, дата; вид работы выбирается из списка, комментарий необязателен.
- [ ] Оценка принимается только в диапазоне 2–5; иначе — сообщение об ошибке.
- [ ] Дата принимается в формате ГГГГ-ММ-ДД или дд.мм.гггг и нормализуется к ISO.
- [ ] Поле не может состоять только из пробелов.
- [ ] После сохранения запись сразу видна в журнале, средний балл пересчитан.

Статус: **данные** (`GradeBookRepository.addGrade`, `GradeRules`, `GradeDate`), форма — спринт 3.

## US-05. Редактирование и удаление оценки

Как студент, я хочу исправить ошибочную или удалить лишнюю оценку, чтобы журнал
оставался достоверным.

**Критерии приёмки**
- [ ] Оценку можно открыть на редактирование, поля заполнены текущими значениями.
- [ ] Изменения проверяются теми же правилами, что и при добавлении.
- [ ] Удаление выполняется после подтверждения.
- [ ] После изменения или удаления пересчитывается средний балл и обновляется список.

Статус: **данные** (`GradeBookRepository.updateGrade`, `deleteGrade`), экран — спринт 3.

## US-06. Расчёт среднего балла

Как студент, я хочу видеть средний балл по дисциплине и общий средний балл,
чтобы оценивать успеваемость.

**Критерии приёмки**
- [ ] Средний по дисциплине = сумма оценок / количество оценок.
- [ ] Общий средний = среднее по всем оценкам всех дисциплин.
- [ ] Контрольный набор 5, 4, 3, 5 даёт 4.25.
- [ ] При отсутствии оценок показывается сообщение, деления на ноль не происходит.
- [ ] В интерфейсе указано, что веса работ не учитываются.

Статус: **данные** (`AVG` + `COALESCE` в `GradeDao`, тест на 4.25 пройден), отображение — спринт 4.

## US-07. Пустые состояния

Как студент, я хочу видеть понятное объяснение вместо пустого экрана, когда данных
ещё нет, чтобы понимать, что делать дальше.

**Критерии приёмки**
- [ ] Нет дисциплин — сообщение «Дисциплин пока нет» и подсказка, как добавить.
- [ ] Нет оценок по дисциплине — «Оценок пока нет» и кнопка добавления.
- [ ] Средний балл при отсутствии оценок не показывается как `0.00`.
- [ ] Экраны не падают при пустых списках.

Статус: **данные** (нули и пустые списки возвращаются корректно), экраны — спринт 3.

## US-08. Фильтрация оценок

Как студент, я хочу отфильтровать оценки по периоду и виду работы, чтобы смотреть
только нужные результаты.

**Критерии приёмки**
- [ ] Фильтр по периоду (с даты / по дату) включительно.
- [ ] Фильтр по виду работы.
- [ ] Фильтр по дисциплине.
- [ ] При пустом результате — понятное сообщение, фильтры можно сбросить.

Статус: **данные** (`GradeDao.getByPeriod`, индексы), интерфейс — спринт 4.

## US-09. Динамика успеваемости

Как студент, я хочу видеть, как менялся средний балл по месяцам, чтобы замечать
ухудшение заранее.

**Критерии приёмки**
- [ ] Средний балл считается по периодам (минимум — по месяцам).
- [ ] Динамика отображается таблицей или графиком.
- [ ] Периоды без оценок не искажают картину.
- [ ] Есть подписи осей/периодов, числа читаемы без пояснений.

Статус: **план** (спринт 4).

## US-10. Калькулятор целевого балла

Как студент, я хочу задать желаемый средний балл и узнать, какая оценка нужна
за следующую работу, чтобы планировать усилия.

**Критерии приёмки**
- [ ] Можно задать целевой средний балл (например, 4.5).
- [ ] Приложение рассчитывает необходимую следующую оценку.
- [ ] Если цель недостижима одной оценкой в диапазоне 2–5, выводится понятное сообщение.
- [ ] Если цель уже достигнута, сообщается, что достаточно любой оценки не ниже 2.

Статус: **план** (спринт 5).

## US-11. Подсветка проблемных дисциплин

Как студент, я хочу видеть, какие дисциплины требуют внимания, чтобы распределять
время.

**Критерии приёмки**
- [ ] Дисциплины со средним баллом ниже порога выделены визуально.
- [ ] Причина выделения объяснена текстом или значком, а не только цветом.
- [ ] Порог задаётся пользователем.

Статус: **план** (спринт 5).

## US-12. Сортировка оценок

Как студент, я хочу сортировать оценки по дате или значению, чтобы быстро находить
лучшие и худшие результаты.

**Критерии приёмки**
- [ ] Выбор направления и поля сортировки.
- [ ] Сортировка не теряет фильтры.
- [ ] Порядок сохраняется при повторном открытии экрана в рамках сеанса.

Статус: **данные** (запросы с `ORDER BY`), интерфейс — спринт 4.
