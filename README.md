# Личный кабинет успеваемости студента

Android-приложение для просмотра учебных оценок, группировки их по дисциплинам,
расчёта среднего балла и отслеживания динамики успеваемости.

Проект выполняется командой из трёх человек по плану из шести спринтов
(36 учебных часов, 1 спринт = 1 учебный день).

| Параметр | Значение |
|---|---|
| Язык | Kotlin |
| Интерфейс | XML-разметка + Activity (View-based) |
| Хранение | Room 2.8.5 поверх SQLite |
| Кодогенерация Room | KSP 2.2.10-2.0.2 |
| Сборка | Gradle 9.6.0, AGP 9.5.2, JDK 17+ |
| minSdk / targetSdk / compileSdk | 24 / 37 / 37 |
| Тесты | JUnit 4 (JVM), AndroidX Test + Room testing (инструментальные) |

## Состояние проекта

| Спринт | Содержание | Статус |
|---|---|---|
| 1 | Анализ требований, сценарии, прототип интерфейса | в работе (макет в Figma) |
| 2 | Модель данных и локальное хранение (Room) | **завершён** |
| 3 | Экран дисциплин и журнал оценок | следующий |
| 4 | Расчёт среднего балла и аналитика | — |
| 5 | Целевой средний балл, UX, тестирование | — |
| 6 | Финальная интеграция, приёмка, защита | — |

На текущий момент готов слой данных: сущности, DAO, база Room, репозиторий
с проверками ввода, демонстрационные данные и тесты. Пользовательских экранов
пока нет — они появляются в спринте 3.

## Как открыть и запустить

1. Открыть папку проекта в Android Studio (JDK 17 или новее, Android SDK 37).
2. Дождаться синхронизации Gradle — Room-код генерируется автоматически (KSP).
3. Запустить `app` на эмуляторе или устройстве (API 24+).

Сборка и тесты из терминала:

```bash
./gradlew assembleDebug            # debug-APK
./gradlew testDebugUnitTest        # юнит-тесты на JVM, эмулятор не нужен
./gradlew connectedDebugAndroidTest # тесты Room на эмуляторе/устройстве
```

## Модель данных (кратко)

```
Discipline (1) ──── (N) Grade
```

* `disciplines`: `id`, `name` (уникальное), `teacher` (необязательно), `created_at`.
* `grades`: `id`, `discipline_id` (внешний ключ, каскадное удаление), `value` (2–5),
  `date` (`yyyy-MM-dd`), `work_type`, `comment` (необязательно), `created_at`.

Подробности, обоснование решений и правила поведения пустой базы —
в [docs/DATA_MODEL.md](docs/DATA_MODEL.md).

## Демонстрационные данные

При самом первом запуске база заполняется вымышленными данными (4 дисциплины,
10 оценок). Одна дисциплина («Физика») намеренно остаётся без оценок — на ней
проверяется пустое состояние и отсутствие деления на ноль. Контрольный набор
«Математический анализ» (5, 4, 3, 5) даёт средний балл 4.25 — пример из ТЗ.

Повторный запуск данные не дублирует: заполнение выполняется только для пустой базы.

## Правила работы с Git

* Основная ветка — `main`; задачи — в ветках `feature/...` и `fix/...`.
* Коммиты осмысленные, на русском: «Добавлены сущности и DAO Room», а не «готово».
* **В репозиторий не попадают** файл задания (`*.docx`) и папка макетов `design/` —
  они перечислены в `.gitignore`.
* Перед слиянием другой участник проверяет, что проект собирается и тесты проходят.
